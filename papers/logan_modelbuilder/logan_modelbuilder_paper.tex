\begin{abstract}
Most current machine assistance for mathematics is syntactic: it proposes statements, searches for proofs, or interacts with proof assistants.  This paper develops a complementary model-side workflow.  We show how \LOGAN{}---Logical GANs based on bounded logical games---can be used to build concrete finite models and countermodels.  A \Builder{} proposes a finite structure; an \Opponent{} (the active Devil) probes it with depth-bounded logical challenges; and a \Judge{} records either a model certificate or a counterexample certificate.  The primitive output is not only a yes/no answer but a small, replayable witness.  The current release implements a generic, signature-parametric \emph{Neural Fra\"iss\'e} proof of concept: over an arbitrary finite signature (relation, function, and constant symbols), an \emph{active symbolic} Devil chooses bounded challenges and a \emph{learned} Builder replies with semantic edits, while the Judge verifies with a bounded checker.  On held-out bounded model/countermodel tasks the learned Builder beats both a random Builder and a symbolic Builder that share the same active Devil.  Finite group theory via Cayley-table synthesis, described later, is a motivating earlier strand and a candidate future domain-specific arena, not the current implemented center.  We give the formal interface, the witness-guided game, the proof-of-concept benchmark, and a companion sub-package with tests.  The resulting system is intended as the model-building flank of AI-assisted mathematics: not replacing proof assistants, but supplying finite witnesses, sanity checks, and counterexamples before proof search hardens a conjecture into a theorem.
\end{abstract}

\section{Introduction}

The standard story of AI-assisted mathematics is still heavily proof-centered.  A language model proposes a lemma; a proof assistant checks a derivation; a human decides whether the result is meaningful.  This is powerful, but incomplete.  Mathematicians do not only prove.  They also build examples, test definitions, search for pathological cases, inspect finite shadows, and ask whether a theory has the intended models.

This paper develops the model-building side of \LOGAN{}.  The central idea is simple:
\begin{quote}
A mathematical object is accepted, for a given budget, if it survives the right bounded adversarial probes; a false conjecture is rejected by producing a small, replayable countermodel witness.
\end{quote}

The workflow has three roles.
\begin{itemize}[leftmargin=2em]
  \item \Builder{} (``God'') proposes and extends a finite partial structure over a generic signature via semantic edits (set a relation cell, a function cell, or a constant); in domain-specific arenas this specializes to Cayley tables, graphs, finite algebras, or arithmetic fragments.
  \item \Opponent{} probes the object with depth-bounded logical challenges.
  \item \Judge{} emits a certificate: model survived, model failed with witnesses, or counterexample to a proposed claim.
\end{itemize}

The conceptual ancestor is the original \LOGAN{} framework, where a bounded logical observer is implemented through Ehrenfeucht--Fra\"iss\'e style games and returns interpretable witnesses.  The present paper turns that idea toward mathematical construction: groups, graphs, arithmetic fragments, and eventually finite categories or other algebraic gadgets.

\paragraph{The current release: a Neural Fra\"iss\'e proof of concept.}
The companion sub-package implements a generic, signature-parametric arena rather than a single algebraic domain.  Over an arbitrary finite signature, an \emph{active symbolic} \Opponent{} (the Devil) chooses bounded challenges against a finite partial structure, and a \emph{learned} \Builder{} (God) replies with semantic edits; a \Judge{} verifies each step with a bounded checker and logs the alternating trace.  On held-out tasks the learned Builder beats non-neural Builders that share the same active Devil (Sections~\ref{sec:nf}--\ref{sec:nf-limits}).  Finite group theory via Cayley tables (Section~\ref{sec:groups}) is a motivating earlier strand and a candidate future domain-specific arena, \emph{not} the current implemented center.

\paragraph{What this is not.}
The goal is not to claim that a bounded finite search proves a general theorem.  The goal is to add a missing semantic instrument to the mathematical workflow: a system that constructs, attacks, repairs, and explains finite models and countermodels with explicit witnesses.

\section{The LOGAN Model-Building Interface}

\subsection{Structures, theories, and attack surfaces}

Fix a finite signature \(\Sigma\).  The current implementation is generic: \(\Sigma\) may contain relation symbols, function symbols, and constants, with no fixed arity bound; the proof-of-concept arena uses \(\Sigma=\{E/2,\,s/1,\,a\}\) (Section~\ref{sec:nf}).  Group theory, \(\Sigma=\{\cdot,e,{}^{-1}\}\), is one illustrative domain-specific specialization (Section~\ref{sec:groups}).

\begin{definition}[Finite candidate structure]
A finite candidate \(\Sigma\)-structure \(A\) consists of a finite domain \(|A|\), interpretations of relation symbols as finite tables, and interpretations of function symbols as total or partial finite maps.  In the group-theory case, \(A\) is represented by a Cayley table
\[
  m_A : |A| \times |A| \to |A|
\]
with a distinguished identity candidate \(e_A\).
\end{definition}

\begin{definition}[Attack surface]
Given a theory \(T\) and a depth parameter \(k\), an attack surface \(\C_k(T)\) is a finite or effectively enumerable collection of bounded challenges.  Each challenge asks whether a bounded instance of an axiom, property, or comparison game is satisfied by \(A\).
\end{definition}

For universal Horn theories, a challenge is usually a tuple.  For example, group associativity is attacked by choosing \((x,y,z)\) and checking
\[
  (x\cdot y)\cdot z = x\cdot (y\cdot z).
\]
If the equation fails, the tuple itself is a witness.

\subsection{Witnesses}

\begin{definition}[LOGAN witness]
A \LOGAN{} witness is a small, replayable object certifying a failed challenge.  Formally it is a tuple
\[
  w = (\mathsf{kind}, \mathsf{payload}, \mathsf{message}),
\]
where \(\mathsf{kind}\) names the failure class, \(\mathsf{payload}\) contains the data needed to replay the failure, and \(\mathsf{message}\) gives a human-readable explanation.
\end{definition}

\begin{example}[Associativity witness]
For a Cayley table \(m\), an associativity witness has the form
\[
  w = (\mathsf{assoc}, x,y,z, m(m(x,y),z), m(x,m(y,z))).
\]
It is valid exactly when the two reported values differ.
\end{example}

\begin{example}[Commutativity counterexample]
To refute ``all groups are abelian'', it is enough to provide a group \(A\) and a pair \((x,y)\) such that
\[
  x\cdot y \neq y\cdot x.
\]
The counterexample certificate must also record that \(A\) passed the group axioms.
\end{example}

\subsection{The LOGAN game for model building}

\begin{definition}[LOGAN model-building game]\label{def:game}
A position is a tuple
\[
  (A,\Cert,\Obl,t),
\]
where \(A\) is the current finite or partial structure, \(\Cert\) is a store of validated facts, \(\Obl\) is a store of existential obligations still to be discharged, and \(t\) is the used budget.  In each round:
\begin{enumerate}[leftmargin=2em]
  \item \Opponent{} chooses a challenge \(c\in \C_k(T)\), subject to total budget \(b\).
  \item If \(c\) fails, \Opponent{} returns a witness \(w\).
  \item \Builder{} either repairs \(A\), extends \(A\), or concedes failure.
  \item \Judge{} updates certificates and logs the trace.
\end{enumerate}
\end{definition}

\begin{definition}[Bounded LOGAN model]
We write
\[
  A \modelslog_{k,b} T
\]
when \Builder{} has a strategy that survives all \Opponent{} challenges from \(\C_k(T)\) up to budget \(b\), while preserving its certificate discipline.
\end{definition}

This is deliberately weaker than classical satisfaction.  It is an operational notion: \(A\) survived a specified adversarial attack surface.

\section{Model Certificates and Counterexample Certificates}

\subsection{Model certificates}

A model certificate records:
\begin{itemize}[leftmargin=2em]
  \item the structure name and representation;
  \item the theory or property suite challenged;
  \item the depth and budget used;
  \item all witness classes checked;
  \item the fact that no failing witness was found.
\end{itemize}

In the finite group setting, a cyclic group \(C_n\) is certified by checking associativity, identity, and inverses over its Cayley table.  For a total table the check can be exhaustive; for a larger or partial structure it can be sampled or budgeted.

\subsection{Counterexample certificates}

A counterexample certificate to a claim
\[
  T \Rightarrow \varphi
\]
records:
\begin{itemize}[leftmargin=2em]
  \item a structure \(A\);
  \item a certificate that \(A\) satisfies or survives the assumptions \(T\);
  \item a witness \(w\) showing that \(\varphi\) fails in \(A\).
\end{itemize}

For example, to refute ``all finite groups are abelian'', \LOGAN{} returns a dihedral group \(D_3\) of order six, verifies the group axioms, then returns a pair \((x,y)\) witnessing non-commutativity.

\section{CEGIS: Witness-Guided Synthesis}

The implementation follows a CounterExample-Guided Inductive Synthesis pattern.  The difference is that the counterexamples are mathematical witnesses rather than ordinary test failures.

\begin{algorithm}[h]
\caption{LOGAN ModelBuilder}
\begin{algorithmic}[1]
\Require theory \(T\), depth \(k\), budget \(b\), builder policy \(\pi\), opponent policy \(\delta\)
\State initialize candidate structure \(A_0\)
\State initialize \(\Cert\gets\varnothing\), \(\Obl\gets\varnothing\), trace \(\tau\gets []\)
\For{iteration \(i=1,\dots,N\)}
  \State \(W,D \gets \Opponent_\delta(A_i,T,k,b)\)
  \If{\(W=\varnothing\) and \(D=\varnothing\)}
    \State \Return model certificate for \(A_i\)
  \EndIf
  \State append \(W,D\) to trace \(\tau\)
  \State \(A_{i+1}\gets \Builder_\pi(A_i,W,D,\Cert)\)
  \State update \(\Cert\) with replayable validated facts
\EndFor
\State \Return failure or unknown with trace \(\tau\)
\end{algorithmic}
\end{algorithm}

\section{Finite Groups: A Motivating Domain-Specific Arena}\label{sec:groups}

\emph{Status note.}  This section describes an earlier motivating strand and a candidate future domain-specific layer.  It is \emph{not} the current implemented center; the current release is the generic Neural Fra\"iss\'e arena of Section~\ref{sec:nf}.  The \texttt{build-group}/\texttt{counterexample} commands and the deterministic builders below are illustrative of a domain specialization and are \emph{not} shipped CLI in the current release; the implemented front door is the \texttt{fight} command of Section~\ref{sec:fight}.

\subsection{Signature and axioms}

The group signature is
\[
  \Sigma_G = \{\cdot,e,{}^{-1}\}.
\]
This domain-specific arena represents the operation by a total Cayley table and treats inverses semantically: an element \(x\) has an inverse when some \(y\) satisfies
\[
  x\cdot y = e = y\cdot x.
\]

The attacked axioms are:
\begin{align*}
  (x\cdot y)\cdot z &= x\cdot (y\cdot z), \\
  e\cdot x &= x = x\cdot e, \\
  \exists y\,(x\cdot y=e \wedge y\cdot x=e).
\end{align*}

Optionally, the \Opponent{} also attacks commutativity:
\[
  x\cdot y = y\cdot x.
\]
This is not a group axiom; it is a target property used to build counterexamples.

\subsection{Implemented builders}

The P0 sub-repository includes deterministic builders for:
\begin{itemize}[leftmargin=2em]
  \item cyclic groups \(C_n\), represented by addition modulo \(n\);
  \item the Klein four group \(V_4\), represented by \(\mathbb{Z}_2\times\mathbb{Z}_2\);
  \item dihedral groups \(D_m\), represented as pairs \((i,j)\) with multiplication
  \[
    (i,j)(k,\ell)=\bigl(i+(-1)^j k \bmod m,\; j+\ell \bmod 2\bigr).
  \]
\end{itemize}

\subsection{Implemented opponents}

The P0 opponent is a Horn-style finite group opponent.  It checks the current structure and returns the first replayable witnesses it finds:
\begin{itemize}[leftmargin=2em]
  \item \texttt{associativity\_failure};
  \item \texttt{identity\_failure};
  \item \texttt{inverse\_failure};
  \item \texttt{commutativity\_failure}, when commutativity is part of the challenge.
\end{itemize}

Later versions should make the budget operational by sampling instances, prioritizing hard tuples, and mixing Horn checks with EF probes.

\subsection{Showcase 1: building a model}

Command:
\begin{lstlisting}[basicstyle=\ttfamily\small]
logan-modelbuilder build-group --kind cyclic --n 5
\end{lstlisting}

Expected status:
\begin{lstlisting}[basicstyle=\ttfamily\small]
{
  "status": "survived",
  "structure": "C_5",
  "order": 5,
  "witnesses": []
}
\end{lstlisting}

Interpretation: \(C_5\) survives the group-theory attack surface.  In a full paper result table, this becomes a model certificate row.

\subsection{Showcase 2: building a counterexample}

Command:
\begin{lstlisting}[basicstyle=\ttfamily\small]
logan-modelbuilder counterexample --claim all_groups_abelian --max-order 8
\end{lstlisting}

Expected status:
\begin{lstlisting}[basicstyle=\ttfamily\small]
{
  "claim": "all_groups_abelian",
  "structure_name": "D_3",
  "structure_order": 6,
  "assumptions_verified": true,
  "refuting_witness": {
    "kind": "commutativity_failure",
    "payload": {"x": ..., "y": ..., "x*y": ..., "y*x": ...}
  }
}
\end{lstlisting}

Interpretation: \LOGAN{} has not merely guessed that the theorem is false.  It has produced a finite group plus a replayable witness to the negation of the target property.

\section{Current Implementation: Neural Fra\"iss\'e POC}\label{sec:nf}

The current release (\texttt{src/logical\_gans/modelbuilder/neural\_fraisse/}) implements a generic, signature-parametric instance of the game of Definition~\ref{def:game}.

\paragraph{Signature and tasks.}
A task fixes a finite signature \(\Sigma\) (relations, functions, constants), a universal Horn/equational theory \(T\), a goal (build a model, or refute a claim \(C\)), and bounded resources: domain size \(n\), depth \(k\), Devil budget \(b\), and a search budget.  The proof-of-concept task family uses \(\Sigma=\{E/2,\,s/1,\,a\}\) with
\[
  T=\{\;\forall x\,E(x,s(x)),\quad \forall x\,s^m(x)=x\;\},
\]
and goals such as building a model or refuting \(s(a)=a\), \(E(a,a)\), or \(\forall x\,E(x,x)\).

\paragraph{Players.}
The roles of Definition~\ref{def:game} are realized concretely:
\begin{itemize}[leftmargin=2em]
  \item \Builder{} (God) answers a challenge with one semantic edit: \(\mathsf{SetRelation}(R,\bar a,\text{true/false})\), \(\mathsf{SetFunction}(f,\bar a,v)\), or \(\mathsf{SetConstant}(c,v)\).
  \item \Opponent{} (active symbolic Devil) \emph{chooses} the next challenge: it points at a specific interpretation cell that currently blocks a bounded axiom instance (a \(\mathsf{ChallengeClauseInstance}\)), or a claim cell that must be committed (a \(\mathsf{ChallengeGoalCell}\)).  This is the decisive change from a passive checker: the Devil drives the cell sequence and the Builder only fills Devil-chosen cells.
  \item \Judge{} verifies each step with the bounded checker \(\texttt{run\_devil\_bounded}(k,b)\) and logs the alternating trace; \(A\modelslog_{k,b}T\) is operationalized as survival of the bounded checker.
\end{itemize}

\paragraph{Arity-parametric learned Builder.}
Each candidate edit is encoded as a \emph{variable-length} sequence of typed tokens (kind; symbol; one positional token per argument; value; game-context), with no fixed maximum arity.  The learned Builder is a small token policy trained by imitation on winning trajectories taken from \emph{training-size} tasks only, and is evaluated on disjoint, larger held-out sizes.

\paragraph{Methods compared.}
Holding the active Devil fixed, three Builders are compared---random reply (\texttt{uniform}), symbolic suggested-value reply (\texttt{obligation\_first}), and the learned reply (\texttt{neural\_active})---together with a fourth method, \texttt{neural\_passive}, which uses the learned policy in free search \emph{without} the active Devil.

\section{Benchmark}\label{sec:nf-bench}

Builders are trained on domain sizes \(n\in\{3,4\}\) and tested on disjoint held-out sizes \(n\in\{5,6\}\), 50 tasks per seed, search budget 800, seeds 0--2.  The committed evidence (\texttt{reports/neural\_fraisse\_poc.md}) reports the cross-seed aggregate:

\begin{center}
\begin{tabular}{lrrr}
\toprule
method & mean success & mean median nodes & total draws \\
\midrule
\texttt{neural\_active}    & 1.00 & 19.0 & 0 \\
\texttt{uniform}           & 0.68 & 522.7 & 35 \\
\texttt{obligation\_first} & 0.33 & 800.0 & 72 \\
\texttt{neural\_passive}   & 0.00 & 800.0 & 108 \\
\bottomrule
\end{tabular}
\end{center}

\noindent\textbf{Baseline definitions.}
\texttt{uniform} = active Devil + random matching reply;
\texttt{obligation\_first} = active Devil + symbolic deterministic reply;
\texttt{neural\_passive} = learned policy without the active Devil (old free search);
\texttt{neural\_active} = active Devil + learned Builder.
Because \texttt{uniform} and \texttt{obligation\_first} share the \emph{same} active Devil as \texttt{neural\_active}, the comparison isolates the learned Builder.  The verdict is \(\mathsf{NEURAL\_FRAISSE\_POC}=\mathsf{PASS}\) on all three seeds: \texttt{neural\_active} beats both same-active-Devil non-neural Builders on success rate, with far fewer nodes and zero draws.

\section{The Fight Command}\label{sec:fight}

A single command runs a fight and prints the alternating trace:
\begin{lstlisting}[basicstyle=\ttfamily\small]
python -m logical_gans.modelbuilder.neural_fraisse.fight \
  examples/problems/cycle3_fight.json
\end{lstlisting}

A representative excerpt (refuting \(s(a)=a\) at \(n=3\)):
\begin{lstlisting}[basicstyle=\ttfamily\small]
Round 1
  Devil: ChallengeClauseInstance clause=edge_to_succ x=0 target=s(0)
  God:   set_function s(0)=1
  Judge: progress
...
Outcome: GOD_WINS
Final structure: a=0; s(0)=1, s(1)=2, s(2)=0; E(0,1),E(1,2),E(2,0)=true
Witness: claim s(a)=a fails: s(a)=s(0)=1 != 0 = a
\end{lstlisting}

Outcomes are \(\mathsf{GOD\_WINS}\) or \(\mathsf{DRAW}\).  The two builder modes are \texttt{active\_symbolic} (active Devil + symbolic Builder) and \texttt{neural\_active} (active Devil + learned Builder).

\section{Limitations}\label{sec:nf-limits}

\begin{itemize}[leftmargin=2em]
  \item one controlled cyclic task family;
  \item active \emph{symbolic} Devil, not a learned Devil;
  \item learned Builder only;
  \item the Builder uses generic game-context features (including collision/image features);
  \item not a GAN;
  \item not full first-order logic;
  \item not a theorem prover;
  \item \(\mathsf{DEVIL\_WINS}\) (certified bounded impossibility) is not implemented in this release.
\end{itemize}

\section{Relation to UCMT}

This paper should be read as the implementation-facing companion to the UCMT line.  UCMT says that bounded modelhood can be formulated as survival against bounded logical challenges.  \LOGAN{} ModelBuilder supplies the computational discipline:
\begin{itemize}[leftmargin=2em]
  \item concrete finite structures;
  \item explicit Opponents;
  \item small witnesses;
  \item model and countermodel certificates;
  \item reproducible traces.
\end{itemize}

The deeper thesis is that model theory can become operational.  A theory is not only a collection of sentences.  It determines an attack surface.  A model-building system is not only a search routine.  It is an adversarial dialogue between construction and falsification.

\section{Conclusion}

\LOGAN{} ModelBuilder is a model-side mathematical assistant.  It does not replace theorem provers; it supplies the finite semantic evidence that should often come before proof search.  The current Neural Fra\"iss\'e proof of concept already captures the essential pattern over a generic finite signature: an active Devil challenges, a learned Builder replies with semantic edits, and a Judge distinguishes model certificates from counterexample certificates---with held-out evidence that the learned Builder beats non-neural Builders under the same active Devil.  The next steps are to make the \emph{Devil} learned and adaptive (an actual adversarial pair), to broaden beyond the single cyclic task family, and to grow domain-specific arenas (groups, monoids, graphs, arithmetic fragments, finite categories) on top of the generic substrate.
